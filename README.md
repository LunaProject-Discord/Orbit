# Orbit

Orbit は、サーバーが IMAP / SMTP や Microsoft Graph でメールを扱い、各クライアントは REST API と SSE でサーバー経由で送受信するメールアプリです。
複数の端末で既読や新着がリアルタイムに一致することを目的にしています。

## 構成

| パス | 内容 |
| --- | --- |
| `apps/api` | API サーバー (Hono)。REST API、SSE、認証 |
| `apps/worker` | 同期ワーカー。IMAP の常時接続、Microsoft Graph の差分取得、送信キューの処理 |
| `apps/web` | Next.js の UI。静的エクスポートし、Web / Tauri / Capacitor で共用する |
| `apps/mobile` | Android アプリ (Capacitor)。`apps/web` の静的出力をアプリに入れる |
| `apps/desktop` | デスクトップ版 (Tauri、Windows / macOS / Linux)。`apps/web` の静的出力をアプリに入れる |
| `packages/db` | PostgreSQL のスキーマとマイグレーション (Drizzle ORM) |
| `packages/core` | サーバー側で共有する処理 (認証情報の暗号化、プロセス間通知の定義) |

## 必要なもの

- Node.js 22 以上
- pnpm 10
- Docker (ローカルの PostgreSQL 19 用)。主キーの UUID v7 に `uuidv7()` を使うため、PostgreSQL 18 以降が必要です

## セットアップ

```sh
pnpm install
pnpm env:init          # .env を作成し、秘密の値 (BETTER_AUTH_SECRET など) を自動生成
docker compose up -d   # PostgreSQL を起動
pnpm db:migrate        # テーブルを作成
pnpm user:create you@example.com "あなたの名前"   # ログイン用の利用者を作成 (パスワードを聞かれます)
pnpm dev               # api / worker / web を起動
```

どのコマンドも Windows (PowerShell)、macOS、Linux で同じように動きます。事前のビルドは不要です
(開発時は `packages/*` の TypeScript を直接読み込みます。`pnpm build` は本番用の出力と型チェックのためのものです)。

Node.js 25 以降には Corepack が同梱されていないため、pnpm は `npm install -g pnpm@10` などで入れてください。

- Web: http://localhost:3000
- API: http://localhost:8787 (`/healthz` で DB 接続を確認できます)

### 同じ LAN のスマホなどから開く

`pnpm dev` を動かしている PC の IP アドレスで、`http://192.168.x.x:3000` のように開けます
(`pnpm dev` を起動したときに `Network:` として表示されるアドレスです)。

- 開発サーバーと API は、起動時にこの PC の名前と IP アドレスを調べて、そこからの通信を許可します。
  IP アドレスが変わったときや、別の名前で開きたいときは、`pnpm dev` を起動し直すか、
  `DEV_ALLOWED_ORIGINS` (Web。ホスト名をカンマ区切り) と `ALLOWED_ORIGINS` (API。オリジンをカンマ区切り) に足してください。
- API の接続先が `localhost` のままでも、画面を開いたのと同じ PC の 8787 番へ自動で向けます。
- PC のファイアウォールで、3000 番と 8787 番への着信を許可しておいてください。
- `http://` の IP アドレスで開いた画面では、ブラウザーの決まりで、オフライン用の保存 (サービスワーカー)、
  閉じているときの通知 (Web Push)、クリップボードへのコピーは使えません。ほかの機能は使えます。
- 本番 (`NODE_ENV=production`) では、この自動の許可は働きません。開発中に止めたいときは `ALLOW_LAN_ORIGINS=false` にします。

## 本番への配置 (Oracle Cloud)

Docker Compose で一式 (Web、API、同期ワーカー、PostgreSQL、バックアップ) を動かします。
外への公開は、別のサーバー (中継用のサーバーや同じサーバーの Apache) から逆プロキシする構成と、同梱の Caddy が直接 HTTPS を受ける構成を選べます。
Docker の導入から、中継の設定、更新、バックアップ、環境変数の一覧までを
[docs/deploy-oracle-cloud.md](docs/deploy-oracle-cloud.md) にまとめています。

```sh
bash deploy/setup.sh orbit.example.com relay    # 別のサーバーから中継する構成 (deploy/.env を作り、秘密の値を生成)
bash deploy/setup.sh orbit.example.com apache   # 同じサーバーの Apache から繋ぐ構成
bash deploy/setup.sh orbit.example.com caddy    # Caddy が 80 / 443 番で直接公開する構成
cd deploy && docker compose up -d --build
```

## ログインとメールアカウント

- アプリへのログインは [Better Auth](https://www.better-auth.com/) のメールアドレス + パスワードです。
  新規登録は API では受け付けておらず (招待制)、最初の利用者は `pnpm user:create` で作成します (管理者になります)。ほかの人は、管理者が「設定」→「利用者と招待」で発行した招待リンクから、自分で登録します。
- クライアントはログインで得たセッショントークンを `Authorization: Bearer` で送ります
  (Web / Tauri / Capacitor で同じ方式を使うため、Cookie には依存しません)。
- 1 人の利用者が複数のメールアカウントを追加できます。アカウントの追加画面で、次の 4 つから選びます。
  - Gmail。Google のログイン画面で認証し (OAuth2)、IMAP / SMTP で同期します。設定は下の「Gmail」を参照してください。
  - Microsoft アカウント (Microsoft 365 の Exchange Online、Outlook.com)。Microsoft のログイン画面で認証し、
    Microsoft Graph で同期します。設定は下の「Microsoft アカウント」を参照してください。
  - iCloud。メールアドレスとアプリ用パスワードだけで追加できます (接続先は自動で設定します)。下の「iCloud」を参照してください。
  - その他のメール。IMAP / SMTP のサーバーを手動で設定し、パスワード (アプリ用パスワードを含む) でログインします。
- メールアカウントのパスワードやリフレッシュトークンは AES-256-GCM で暗号化して保存します。鍵は `CREDENTIALS_ENCRYPTION_KEY` で、
  DB には入りません。鍵を失うと復号できなくなるため、安全な場所に控えてください。
- メールの本文や添付ファイルは、サーバー側の検索などに使うため、DB やディスクにはそのままの形で保存します
  (ディスクの暗号化は、サーバーや端末の機能に任せています)。本番の構成では、サーバーの間の通信は HTTPS で、
  バックアップは公開鍵で暗号化して書き出せます ([docs/deploy-oracle-cloud.md](docs/deploy-oracle-cloud.md))。
- ローカルの IMAP サーバー (localhost や内部 IP) で試す場合は、`.env` で `ALLOW_PRIVATE_MAIL_HOSTS=true` にします。

## ログインとセキュリティ (パスワード、2 段階認証、パスキー)

Orbit 自体のアカウントは、設定画面の「ログインとセキュリティ」で利用者が自分で管理できます。

| できること | 内容 |
| --- | --- |
| パスワードの変更 | いまのパスワードを確かめて変更します。「ほかの端末をログアウトする」を選べます |
| パスワードの再設定 | ログイン画面の「パスワードを忘れた場合」から、再設定のリンクをメールで受け取ります (有効期限 1 時間)。再設定すると、すべての端末がログアウトになります |
| メールアドレスの変更 | いまのパスワードを確かめたうえで、新しいアドレスへ確認のメールを送ります。リンクを開くと変更が完了します (有効期限 1 時間)。いまのアドレスにも、申し込みがあったことを知らせます |
| 2 段階認証 | 認証アプリ (TOTP) の 6 桁のコードと、バックアップコード 10 個。「この端末では 30 日間コードを尋ねない」を選べます。コードを 10 回続けて間違えると、15 分間ログインできません |
| パスキー | 端末の指紋・顔・PIN やセキュリティキーでログインします。パスキーでのログインでは、2 段階認証のコードは尋ねません |

**メールの送信**: パスワードの再設定とメールアドレスの変更は、Orbit 自身がメールを送ります。利用者のメールアカウントとは別に、
送信用の SMTP サーバーを `SYSTEM_MAIL_*` で設定してください。

```sh
SYSTEM_MAIL_HOST=smtp.example.com
SYSTEM_MAIL_PORT=587                          # 既定は 587 (STARTTLS)。465 なら最初から TLS
SYSTEM_MAIL_USER=no-reply@example.com
SYSTEM_MAIL_PASSWORD=...
SYSTEM_MAIL_FROM="Orbit <no-reply@example.com>"
```

Microsoft 365 のメールボックスから送るときは、SMTP の代わりに Microsoft Graph の `sendMail` を使えます
(Microsoft 365 の SMTP は、パスワードでのログインが廃止される予定のため)。`SYSTEM_MAIL_GRAPH_SENDER` (差出人のメールボックス) と
`SYSTEM_MAIL_GRAPH_TENANT` (テナントの ID) を書き、アプリ登録に `Mail.Send` の「アプリケーションの許可」と管理者の同意を付けます。
手順は [docs/deploy-oracle-cloud.md](docs/deploy-oracle-cloud.md) の「Microsoft 365 から送る」を参照してください。
SMTP とは、どちらか一方だけを設定します。

- 未設定のとき、開発中 (`NODE_ENV` が `production` 以外) は、送るはずのメールの内容を API サーバーのログに出します
  (リンクをそこから開いて試せます)。本番では、再設定とメールアドレスの変更が使えなくなり、画面にも出しません。
  パスワードの変更、2 段階認証、パスキーは、メールを送れなくても使えます。
- パスワードを忘れ、メールも送れないときは、サーバー上で `pnpm user:password <メールアドレス>`
  (本番は [docs/deploy-oracle-cloud.md](docs/deploy-oracle-cloud.md) を参照) でパスワードを付け直せます。
  `--reset-two-factor` を付けると、2 段階認証も解除します (認証アプリとバックアップコードを両方失ったとき)。

**パスキーを使える環境**: パスキーは Web のドメイン (`PASSKEY_RP_ID`。既定は `ALLOWED_ORIGINS` の先頭の URL のホスト名) に結び付きます。

- ブラウザーで開いた Web 版では使えます (HTTPS か localhost が必要です)。
- Android アプリ (Capacitor) とデスクトップ版 (Tauri) では、パスキーの登録もログインもできません。アプリの画面は
  `https://localhost` や `tauri://localhost` といったアプリ内のオリジンで動いていて、WebAuthn の決まりでは、
  ページのオリジンと違うドメインのパスキーは扱えないためです。アプリではボタンを出さず、パスワード (+ 2 段階認証) でログインします。
  アプリで使うには、OS のパスキーの仕組み (Android の Credential Manager など) を直接呼ぶ実装が別に必要です。
- ドメインを変えると、登録済みのパスキーは使えなくなります (登録し直しになります)。

**仕組み**: Better Auth の `twoFactor` と `@better-auth/passkey` を使っています。この API は Cookie を使わないので、
Better Auth が Cookie に置く途中の値 (2 段階認証の途中のログイン、信頼した端末の印、パスキーのチャレンジの控え) は、
`X-Auth-State` ヘッダーで画面に預けて、次の呼び出しで返してもらいます (`apps/api/src/lib/auth-state.ts`、
`apps/web/src/lib/auth-state.ts`)。値は Better Auth が署名しているので、画面側で書き換えても通りません。

## Gmail (Google でログイン)

Gmail は、Google のログイン画面で許可を受け (OAuth2)、受け取ったトークンで IMAP / SMTP にログインします (XOAUTH2)。
Google のパスワードやアプリ パスワードをこのアプリに保存する必要はありません。
使うには、[Google Cloud コンソール](https://console.cloud.google.com/) で OAuth クライアントを作ります。
以下は 2026 年 11 月時点の手順で、公式ドキュメントとの照合はできていません。画面の名称は変わることがあります。

1. プロジェクトを作り (既存のものでも構いません)、「API とサービス」→「OAuth 同意画面」
   (「Google Auth Platform」と表示されることもあります) を開いて、アプリ名と連絡先のメールアドレスを設定します。
   対象 (ユーザーの種類) は、個人の Gmail で使うなら「外部」、Google Workspace の組織内だけで使うなら「内部」を選びます。
2. 「データアクセス」(スコープ) で、`https://mail.google.com/` を追加します。IMAP / SMTP に OAuth2 でログインするには
   このスコープが必要で、Google はこれを「制限付きスコープ」に分類しています。
3. 「対象」で公開ステータスを決めます (「外部」を選んだ場合)。
   - 「テスト中」のままだと、追加するアカウントを「テストユーザー」に登録する必要があり、**ログインが 7 日で切れます**
     (7 日ごとに「Google にログインし直す」が必要になります)。動作確認にはこれで十分です。
   - 続けて使うなら「本番環境」に切り替えます。Google の審査を受けていないアプリは、ログイン時に
     「このアプリは Google で確認されていません」という警告が出ますが、「詳細」から進めば使えます
     (未審査のアプリを使える人数には上限があります)。自分や身内だけで使うなら、審査を受けずにこの状態で使えます。
4. 「クライアント」→「クライアントを作成」で、種類を「ウェブ アプリケーション」にします。
   「承認済みのリダイレクト URI」に、Web の URL に `/oauth/google` を付けたものを登録します
   (ローカルなら `http://localhost:3000/oauth/google`)。`GOOGLE_REDIRECT_URI` と完全に一致させてください。
5. 表示されたクライアント ID とクライアント シークレットを `.env` の `GOOGLE_CLIENT_ID` と `GOOGLE_CLIENT_SECRET` に設定し、
   api と worker を再起動します (どちらにも必要です)。

設定すると、アカウントの追加画面の「Gmail」から追加できます。ログイン画面の確認では、
「Gmail のすべてのメールの閲覧、作成、送信、完全な削除」にチェックを入れてください (外すと追加できません)。
設定していないサーバーでは、「その他のメール」から Google のアプリ パスワードで追加することもできます
(IMAP は `imap.gmail.com` の 993 番、SMTP は `smtp.gmail.com` の 465 番。接続先が Gmail なら、下の扱いは同じです)。

- Gmail ではフォルダが実際には「ラベル」で、1 通のメールが、付いているラベルの数だけ IMAP のフォルダに現れます。
  同じメールは Gmail のメッセージ ID (X-GM-MSGID) で 1 通にまとめて取り込むので、DB や一覧で重複しません。
- 「すべてのメール」も同期します (アーカイブしたメールはここにだけ残るため)。「スター付き」と「重要」は、
  ほかのフォルダのメールを集めて見せているだけなので同期しません (スターはメールの印として同期します)。
- アーカイブは、受信トレイから外す操作です (メールは「すべてのメール」に残り、ほかのラベルは外しません)。
  ラベルへの移動は、受信トレイにあるメールなら受信トレイから、無ければ付いているラベルから移します。
  削除はごみ箱への移動で、すべてのラベルから消えます。
- 送信したメールは Gmail が自動で「送信済みメール」に保存するので、こちらからは保存しません (二重になりません)。
- アクセストークンは 1 時間で切れるので、ワーカーがリフレッシュトークンで取り直します。IMAP の接続は
  トークンの期限で切られることがあり、その場合は自動でつなぎ直します。
- リフレッシュトークンが失効した場合 (公開ステータスが「テスト中」で 7 日たった、Google アカウントの設定でアクセスを
  取り消した、パスワードを変更したなど) は、サイドバーに「再ログインが必要です」と表示されます。
  「Google にログインし直す」から復旧できます。
- Google Workspace のアカウントでは、管理者が IMAP やサードパーティ製アプリのアクセスを制限していると追加できません。

## iCloud

アカウントの追加画面で「iCloud」を選び、iCloud メールのアドレス (`@icloud.com`、`@me.com`、`@mac.com`) と
アプリ用パスワードを入力します。接続先 (IMAP は `imap.mail.me.com` の 993 番、SMTP は `smtp.mail.me.com` の 587 番) は
自動で設定します。

- Apple Account のパスワードではログインできません。[account.apple.com](https://account.apple.com/) にサインインし、
  「サインインとセキュリティ」→「アプリ用パスワード」で、このアプリ専用のパスワードを作ってください
  (2 ファクタ認証を有効にしている必要があります)。
- Apple Account のパスワードを変更すると、アプリ用パスワードはすべて無効になります。その場合は作り直して、
  アカウントを追加し直してください (パスワードだけを更新する画面はまだありません)。
- ユーザー名にはメールアドレスをそのまま使います。カスタム メール ドメインのアドレスなどでログインできない場合は、
  「その他のメール」から、ユーザー名に iCloud メールのアドレスを指定して追加してください。
- 送信したメールの控えは、こちらから「送信済み」フォルダへ保存します。

## 古い TLS のメールサーバー

「その他のメール」で追加するときに `unsafe legacy renegotiation disabled` というエラーで
接続できない場合、そのサーバーは TLS の安全な再ネゴシエーション (RFC 5746) に対応していません。
追加の画面にその旨が出て、「古い TLS のサーバーへの接続を許可する」スイッチが現れます。
オンにして追加すると、そのアカウントの IMAP と SMTP の接続にだけ OpenSSL の
`SSL_OP_LEGACY_SERVER_CONNECT` を付けます (`mail_accounts.allow_legacy_tls`)。
あとから設定画面のアカウントの欄でも切り替えられます。

- 通信の暗号化、証明書の検証、TLS のバージョンの下限 (1.2) は変わりません。
- 通信経路に割り込める相手が、接続の先頭にデータを差し込める弱点 (CVE-2009-3555) が残ります。
  サーバー側を更新できるなら、そちらが本来の対処です。
- ほかのアカウントや、Gmail・iCloud・Microsoft の接続には影響しません。

## Microsoft アカウント (Exchange Online / Outlook.com)

Microsoft Graph を使うには、[Microsoft Entra 管理センター](https://entra.microsoft.com/) でアプリを登録します。

1. 「アプリの登録」→「新規登録」を開き、名前を付けます。「サポートされているアカウントの種類」は、
   組織と個人の両方を使うなら「任意の組織ディレクトリ内のアカウントと個人用 Microsoft アカウント」を選びます。
2. リダイレクト URI は種類を「Web」にして、Web の URL に `/oauth/microsoft` を付けたものを登録します
   (ローカルなら `http://localhost:3000/oauth/microsoft`)。`MICROSOFT_REDIRECT_URI` と完全に一致させてください。
3. 「証明書とシークレット」でクライアント シークレットを作り、値を控えます (有効期限が切れたら作り直しが必要です)。
4. 「API のアクセス許可」で Microsoft Graph の委任されたアクセス許可 `offline_access`、`User.Read`、
   `Mail.ReadWrite`、`Mail.Send` を追加します。
5. `.env` の `MICROSOFT_CLIENT_ID` (アプリケーション ID) と `MICROSOFT_CLIENT_SECRET` を設定し、api と worker を再起動します。
   「サポートされているアカウントの種類」で組織のみ / 個人のみを選んだ場合は、`MICROSOFT_TENANT` も合わせます。

設定すると、アカウントの追加画面の「Microsoft」から追加できます。
組織のアカウントでは、テナントの設定によって管理者の同意が必要な場合があります。

- 同期は [差分取得 (delta query)](https://learn.microsoft.com/graph/delta-query-messages) で行います。確認の間隔は状況に応じて変わります
  (下の「更新の速さ」を参照)。
- `API_PUBLIC_URL` が公開された HTTPS の URL (localhost や IP アドレスではないもの) なら、
  [変更通知 (Webhook)](https://learn.microsoft.com/graph/change-notifications-delivery-webhooks) を自動で購読し、
  通知が届いたらすぐに差分を確認します。Microsoft Graph から `POST {API_PUBLIC_URL}/v1/webhooks/microsoft` に
  届く必要があります。購読は 6 日の期限で作り、期限の 2 日前に自動で延長します。購読に失敗した場合は
  ワーカーのログに理由を出し、定期的な確認だけで同期を続けます (1 時間後に試し直します)。
- メッセージは [不変 ID](https://learn.microsoft.com/graph/outlook-immutable-id) で識別します。
- フォルダはサブフォルダも含めて取り込みます。
- 添付ファイルは一覧だけを取り込み、実体は開いたときに取得します (下の「受信したメールの添付ファイル」を参照)。
- 現時点では返信済みの印は取り込みません。
- リフレッシュトークンが失効した場合 (長期間の未使用、パスワード変更、同意の取り消しなど) は、
  サイドバーに「再ログインが必要です」と表示されます。「Microsoft にログインし直す」から復旧できます。

## 受信したメールの添付ファイル

添付ファイルは、メールの取り込みでは一覧 (名前、種類、大きさ) だけを DB に入れ、実体はメールサーバーに
置いたままにします。画面で開いたとき (プレビュー、保存、本文に埋め込まれた画像の表示、転送) に、
API がワーカーへ `NOTIFY` で頼み、ワーカーがメールサーバーから取得して `ATTACHMENTS_DIR` に置き、
API がそれを返します。IMAP では取得のときだけ同期用とは別の接続を張り、30 秒使われなければ閉じます。
置いた写しは送信用の添付ファイルと同じく 7 日で消え、その後に開いたときは取得し直します。
1 件あたり 150 MB を超える添付ファイルは取得しません。

画面の中でプレビューできるのは、画像 (PNG / JPEG / GIF / WebP / AVIF / BMP)、PDF、テキストです。
添付ファイルの中身は差出人が自由に決められるので、API は必ず「ファイルとして保存」の扱いで返し、
画面側も種類を決め打ちした上で表示します (HTML や SVG はプレビューしません)。

## 同期の仕組み

1. API がアカウントを保存すると、PostgreSQL の `NOTIFY` で同期ワーカーに伝わります。
2. ワーカーはアカウントごとに IMAP へ常時接続し (Microsoft アカウントでは Microsoft Graph を定期的に確認し)、全フォルダを DB に取り込みます
   (先に一覧、続いて本文を取得)。以降、受信トレイは IMAP IDLE で新着・既読・削除の通知を受けて差分を反映します。
   IDLE で通知を受けられるのは接続ごとに 1 つのフォルダだけなので、他のフォルダは通知用の接続を別に張って変化を受け取り
   (下の「更新の速さ」を参照)、通知を受けられないフォルダは 2 分ごとに件数や変更番号 (STATUS) を確認して、
   変化のあったフォルダだけを開いて突き合わせます。
3. ワーカーは変更を `changes` テーブルに記録して `NOTIFY` し、API が SSE (`GET /v1/events`) で各端末に知らせます。
   端末は `GET /v1/sync?since=<変更番号>` や一覧 API で取り直します。

フォルダはサブフォルダも含めて同期し、サイドバーにアカウントごとのツリーで表示します。送信済み、下書き、ごみ箱、
迷惑メール、アーカイブなどの役割は、IMAP では SPECIAL-USE (無ければフォルダ名)、Microsoft Graph では既定フォルダ名
(`sentitems` など) で判定します。メールを開くと既読になり、既読 / 未読の切り替え、スター、
アーカイブ、削除 (ごみ箱へ移動)、フォルダへの移動ができます。操作はまず画面と DB に反映し、
送信待ちキュー (outbox) から同期ワーカーがメールサーバーへ反映します。

サイドバーのフォルダとアカウントは、ドラッグ (タッチでは長押ししてからドラッグ) か、項目にフォーカスを置いて
`Alt` + `↑` / `↓` で並び替えられます。フォルダは同じ親の中で入れ替えます。並び順はサーバーの DB に保存するので、
ほかの端末にも同じ順で表示されます。変えるのは表示順だけで、メールサーバー側のフォルダ (名前や親子関係) は変えません。
並び替えた後にできたフォルダは、並び替えたフォルダの後ろに既定の順 (役割、次に名前) で並びます。
メールの移動先のメニュー (ツールバー、右クリック、`V` キー) も、サイドバーと同じ並び順とアイコンで表示します。

サイドバーのフォルダとアカウントは、右クリック (タッチでは動かさずに長押し) でメニューを開けます。
フォルダでは「すべて既読にする」と並び替え (上へ / 下へ、元に戻す)、アカウントでは「今すぐ同期」、並び替え、
署名の編集、設定、削除ができます。

フォルダの新規作成 (アカウントの最上位か、フォルダの中)、名前の変更、削除も右クリックメニューからできます。
これらはメールサーバー上のフォルダを変える操作で、送信待ちキュー (outbox) から同期ワーカーが IMAP
(CREATE / RENAME / DELETE) または Microsoft Graph (mailFolders) へ反映し、そのあとのフォルダ一覧の同期で画面に出ます。
名前の変更では、取り込み済みのメールと並び順はそのまま残ります。受信トレイなどの役割があるフォルダは名前の変更と
削除ができず、中にフォルダがあるフォルダは削除できません。メールサーバーに拒否されたときは、画面の下に知らせます。

迷惑メールのフォルダがあるアカウントでは、ツールバーと右クリックメニューに「迷惑メールにする」が出ます
(迷惑メールのフォルダの中では「迷惑メールから戻す」になり、受信トレイへ戻します)。ショートカットは `!` です。

### 反映に失敗したときの通知

既読や移動などの操作をメールサーバーへ反映できなかったとき (サーバーに拒否された、やり直しても通らなかったなど) は、
画面の下に「1 件の移動をサーバーに反映できませんでした」と知らせます。画面と DB の表示は、次の同期でメールサーバーの
状態に戻します。

- 「再試行」で、もう一度メールサーバーへ反映します。「詳細」で、操作ごとの理由の確認、個別の再試行、破棄ができます。
- 知らせは、再試行で成功するか破棄するまで、どの端末にも出し続けます。7 日たった失敗の記録は自動で消します。
- API は `GET /v1/messages/failures`、`POST /v1/messages/failures/:id/retry`、`DELETE /v1/messages/failures/:id` です。
- 送信の失敗は、これとは別に一覧の上部に表示します (編集して送り直せます)。

### 新着メールの通知

受信トレイに新しいメールが届くと、ブラウザーの通知で知らせます。サイドバー下部のベルのボタンから、
ブラウザー (端末) ごとに有効にします。タブの題名には、受信トレイの未読数を `(3) Orbit` のように出します。

- 通知するのは、同期を始めたあとに受信トレイへ届いた未読のメールです。初回の取り込み、ほかの端末で既読にしたメール、
  24 時間より前に受信したメールは通知しません。1 回の同期で 4 通以上届いたときは、1 件の通知にまとめます。
- `.env` に `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` があれば (`pnpm env:init` が生成します)、
  [Web Push](https://developer.mozilla.org/docs/Web/API/Push_API) で送るので、画面を閉じていても届きます。
  同期ワーカーから各ブラウザーのプッシュサービス (Google、Mozilla、Apple、Microsoft) へ HTTPS で接続できる必要があります。
  `VAPID_SUBJECT` には、プッシュサービスからの連絡先 (`mailto:` のメールアドレスか `https://` の URL) を設定してください。
- 鍵が無い場合や、ブラウザーが Web Push に対応していない場合は、画面を開いている間だけ通知します。
- Web Push とスマホアプリの通知には、メールを開かずに操作できるボタンが付きます (1 通ずつの通知のみ)。
  「既読にする」「スターを付ける」「アーカイブ」「削除」「迷惑メール」から 3 つまでを、設定画面の「通知に付けるボタン」で選びます
  (すべての端末で共通。ブラウザーが並べられる数は Chrome で 2 つ)。ボタンは `POST {API_PUBLIC_URL}/v1/notification-actions` を呼び、
  ログインの代わりに、通知ごとの合言葉 (その 1 通だけを 7 日間操作できる) で確かめます。
- Web Push とサービスワーカーは、HTTPS で開いたページ (または `localhost`) でだけ使えます。
  iOS / iPadOS の Safari では、ホーム画面に追加したときにだけ使えます。
- ログアウトすると、そのブラウザーへの通知を止めます。鍵を作り直した場合は、各ブラウザーが次に画面を開いたときに登録し直します。
- Android アプリへは Firebase Cloud Messaging (FCM) で送ります。`.env` に `FCM_SERVICE_ACCOUNT` (Firebase のサービスアカウントの鍵) が
  あるときだけ送ります。準備は [docs/android-app.md](docs/android-app.md) を参照してください。

### メールの送信

新規作成、返信、全員に返信、転送ができます。本文には太字・斜体・下線・箇条書き・リンクを使え、
テキスト版と HTML 版の両方を入れて送ります。ファイルを添付できます。

作成画面は、広い画面では右下に開く窓で、開いたままほかのメールを読めます。書きかけの内容は
下書きとしてサーバーに自動で保存し、サイドバーの「下書き」から、どの端末でも続きを書けます
(付けたファイルも引き継ぎます)。送信すると下書きは消えます。同じ下書きを 2 台で同時に書き換えた場合は、
後から保存した端末の内容を別の下書きとして残します。
下書きは、書く手が 20 秒止まるとメールサーバーの下書きフォルダにも保存するので、ほかのメールソフトからも見えます
(IMAP は追加してから前の控えを削除、Microsoft Graph は同じメッセージを書き換え)。下書きフォルダに並んだ控えを開くと、
作成画面で続きを書けます。ほかのメールソフトで作った下書きは表示だけで、このアプリでの編集にはまだ対応していません。サーバーへ保存し終えるまでの間は
ブラウザーの中にも置いておくので、通信できないときに閉じても内容は失われません。

添付ファイルは、作成画面で選んだ時点で `POST /v1/attachments` がサーバーの `ATTACHMENTS_DIR`
(既定はリポジトリ直下の `data/attachments`) に置き、送信のときにワーカーが読みます。API サーバーとワーカーの
両方から同じディレクトリが見える必要があります。置いてから 7 日たったファイルは、ワーカーが消します (下書きに付いているファイルは残します)。
上限は 1 通あたり合計 25 MB、20 件です。Microsoft のアカウントでは、Microsoft Graph の制限に収まるよう合計 3 MB までにしています。

1. `POST /v1/messages/send` が送信待ちキューに積み、すぐに応答します。
2. 同期ワーカーが、IMAP のアカウントは SMTP で、Microsoft のアカウントは Microsoft Graph (`sendMail`) で送ります。
3. 送信済みフォルダへの控えは、Gmail / Microsoft はサーバーが自動で保存します。それ以外の IMAP アカウントでは、
   ワーカーが送信済みフォルダへ保存します (同じ Message-ID のメールがすでにあれば保存しません)。
4. 返信した元のメールには、返信済みの印を付けます (Microsoft Graph では、このアプリの中だけの表示です)。

一時的な失敗 (接続できない、4xx の応答) は間隔を空けて 5 回までやり直します。拒否された場合と、
本文の送信中に接続が切れて届いたかどうか分からない場合は、二重に送らないようやり直さず、
画面の一覧の上に理由を表示します (編集して送り直すか、破棄できます)。

SMTP は、`smtpSecure` が有効なら最初から TLS、無効なら STARTTLS を必須にして接続します。
`ALLOW_PRIVATE_MAIL_HOSTS=true` (開発用) のときだけ、TLS の無い SMTP サーバーにも接続します。

### 更新の速さ

同期ワーカーは、状況に応じて確認の方法と間隔を切り替えます。画面を開いている端末は、表示中のフォルダを
30 秒ごとに `POST /v1/focus` で知らせます (知らせが 75 秒途絶えると、開いていない扱いに戻ります)。

| 対象 | IMAP | Microsoft Graph |
| --- | --- | --- |
| 受信トレイ | IDLE で即時 | 画面を開いている間は 5 秒ごと、それ以外は 15 秒ごと |
| 画面で開いているフォルダ | もう 1 本接続を張って IDLE で即時。張れないとき (同時接続数の上限など) は 10 秒ごとに STATUS で確認 | 受信トレイと同じ間隔 |
| 他のフォルダ | 通知用の接続で即時 (下記)。通知を受けられないフォルダは 2 分ごとに STATUS で確認 | 変更通知 (Webhook) が届けば即時、届かなければ 2 分ごと |
| 移動などの操作の直後 | すぐに全フォルダを確認 | すぐに全フォルダを確認 |

IMAP の受信トレイ以外のフォルダは、サーバーに合わせて次のどちらかで変化を受け取ります。

- **NOTIFY ([RFC 5465](https://www.rfc-editor.org/rfc/rfc5465)) に対応したサーバー (Dovecot など)**: 接続を 1 本だけ足し、
  全フォルダのメールの追加・削除・フラグの変化と、フォルダの作成・削除・名前の変更を受け取ります。
  届いている間は、全フォルダの定期的な確認を取りこぼしに備えた 10 分ごとに落とします。
- **それ以外のサーバー**: 大事なフォルダから順に、フォルダごとに接続を 1 本ずつ張って IDLE します。順番は
  迷惑メール、送信済み、利用者が作ったフォルダ (最近メールが届いた順)、アーカイブ、下書き、ごみ箱です。
  Gmail は「すべてのメール」(迷惑メールとごみ箱以外の全メールが入っている) を見張り、変化があれば全フォルダを確認するので、
  「すべてのメール」と「迷惑メール」の 2 本で全ラベルの変化が分かります。

足す接続の本数は、設定の「アカウント」にある「ほかのフォルダの変化をすぐ受け取る」で、アカウントごとに決められます
(自動 / 使わない / 1〜8 本)。自動は Gmail が 2 本、それ以外は 3 本です。メールサーバーには同時接続数の上限があり
(Gmail は 1 アカウント 15 本、Dovecot の既定は 1 つの IP アドレスから 10 本)、同期用 1 本、開いているフォルダ用 1 本、
本文や添付の取得用 1 本を別に使うので、他のメールソフトの分を残せるよう控えめにしてあります。
接続を張れなかった場合 (上限に当たった場合など) は、張れている本数までに 30 分抑え、残りのフォルダは 2 分ごとの確認で同期します。
同期用の接続そのものが、同時接続数の上限や混雑でログインを断られた場合 (サーバーはこれを認証の失敗と同じ形で返します) は、
パスワードの誤りとは区別して再ログインを求めず、フォルダ用の接続をすべて手放して 30 分は張らずに、間隔を空けてつなぎ直します。

Microsoft Graph では、さらに次のように調整します。

- 変更通知 (Webhook) が実際に届いている間は、通知を受けてすぐに確認し、定期的な確認は取りこぼしに備えた間隔
  (画面を開いている間は 1 分、それ以外は 5 分) に落とします。定期的な確認のほうが先に変化を見つけた場合は、
  通知が届いていないとみなして元の間隔に戻します。
- 制限 (429) を受けたら `Retry-After` に従って待ち、確認の間隔を倍に延ばします (最大 8 倍)。
  5 分間制限を受けなければ半分に戻します。Outlook の制限は 1 つのメールボックスにつき 10 分で 10,000 回、
  同時 4 件です ([Microsoft Graph の制限](https://learn.microsoft.com/graph/throttling-limits#outlook-service-limits))。

## オフライン

Web の画面 (Tauri / Capacitor に同梱する場合も同じ) は、サーバーに届かないときも開けて、保存済みのメールを読めます。

- **アプリ本体**: サービスワーカー (`apps/web/public/sw.js`) が、HTML・スクリプト・スタイルを端末に保存します。
  保存する一覧は、ビルドのたびに `out/precache-manifest.json` として作られます (`apps/web/scripts/precache-manifest.mjs`)。
  フォントは数が多いので、表示に使った分だけ保存します。`pnpm dev` (next dev) では一覧が無いので、何も保存しません。
  サービスワーカーは HTTPS か localhost でだけ動きます。
- **メールのデータ**: サーバーから取得したアカウント、フォルダ、一覧、本文、会話、下書きを IndexedDB (`mail-offline-<利用者の ID>`) に保存し、
  サーバーに届かないときはそこから表示します。一覧に出たメールの本文は、開く前に少しずつ取得して保存します
  (本文は 3,000 通まで。超えたら受信の古いものから消します)。一度開いた添付ファイルは、3 MB までのものを 60 件まで保存します。
  表示したことのないフォルダと、読み込んでいない古いメールは、オフラインでは表示できません。
- **検索**: オフラインでは、端末に保存したメールから探します (書き方はサーバーの検索と同じ)。本文は、保存済みのものだけが対象です。
- **操作**: 既読・スター・移動・削除は、端末に貯めておき、届くようになったら順に送ります (オンラインのときと同じ待ち行列)。
- **送信**: サーバーに届かないときに送信したメールは端末で預かり、届くようになったら自動で送ります。預かっている間は、
  一覧の上に「接続後に自動で送信します」と出て、編集に戻すことも取り消すこともできます。
  オフライン中は、新しいファイルを添付できません (添付はサーバーへ送って預ける方式のため)。
- **食い違ったとき**: 操作と送信には 1 件ずつ ID を付けているので、送り直しても二重には実行されません。
  既読やスターは、あとからサーバーに届いた操作が勝ちます。対象のメールが他の端末で消されていたなど、サーバーに断られた操作は取り消して、
  一覧をサーバーの状態に戻します。下書きは、他の端末が先に書き換えていたら、この端末の内容を別の下書きとして残します。
  サーバーに断られた送信は、理由を添えて一覧の上に残します。
- **ログアウト**: 自分でログアウトすると、端末に保存した内容 (預かっている未送信のメールを含む) を消します。
  セッション切れでは消さず、ログインし直すと続きから使えます。

仕組みは `apps/web/src/lib/offline/` にまとめています。保存先は `LocalStore` (`store.ts`) という小さな形だけに頼っているので、
端末の SQLite などに置き換える場合は、これを実装したものを `openOffline` に渡します。

## API (v1)

| メソッドとパス | 内容 |
| --- | --- |
| `POST /v1/auth/sign-in/email` | ログイン。レスポンスヘッダー `set-auth-token` がセッショントークン |
| `POST /v1/auth/sign-out` | ログアウト |
| `GET /v1/me` | ログイン中の利用者 |
| `GET /v1/auth-features` | サーバーが利用者へメールを送れるか (ログイン前の画面が、再設定の案内を出すかどうかに使う) |
| `POST /v1/auth/request-password-reset`、`POST /v1/auth/reset-password` | パスワードの再設定 (メールのリンクの合言葉で新しいパスワードを設定) |
| `POST /v1/auth/change-password` | パスワードの変更 |

## 検索

サーバーに同期済みのメール (全フォルダ) を、件名・差出人・宛先・本文の部分一致で探します。メールサーバーへは問い合わせません
(本文は同期ワーカーが後追いで全通取得するので、取得が終われば本文も対象になります)。HTML だけのメールは、タグを除いた文字列が対象です。

- Web とデスクトップでは、画面の右上 (メールの表示の上。一覧だけを出す幅では一覧の見出しの右) の検索欄に入力すると、
  入力が止まったところで検索します (`/` キーで検索欄へ移動、Enter ですぐに検索)。欄が狭いときは虫めがねだけを出し、押すと広がります。
- 検索欄を押すと、下に候補が出ます。`from:` などの書き方 (検索オプション)、入力中の語に当たる相手のアドレス、
  `after:` / `before:` のカレンダー、`has:` / `is:` の値、`folder:` のフォルダ (全アカウントのフォルダを名前でまとめたもの)、この端末の最近の検索 (`mail.search-history.v1`) を、矢印キーと Enter (または Tab) で選べます。
- `from:` などの条件は、コロンを入れた時点で欄の中のチップになり、値はそのチップの中で入力します (空白か Enter で確定)。
  チップの × で外せます。欄の先頭で Backspace を押すと、直前のチップの値をもう一度入力できます。
  確定したチップは、押すか、欄の端で ← / → を押すと、その場で値を直せます (空白・Enter・Esc で確定)。
  チップと入力欄は、まとめて横にスクロールします。
- 最近の検索は、行の × (選んでいる行は Delete キー) で 1 件ずつ、「すべて消す」でまとめて消せます。
- メールを開いているときは、候補の「このメールの中で〜を探す」で、開いているメールの中 (件名・見出し・本文) を探せます。
  スマホ幅ではメールの「その他の操作」から、デスクトップ版では Ctrl+F (macOS は ⌘F) でも開けます。Enter / Shift+Enter で次 / 前へ移ります。
  会話の中で閉じているメールは対象外です。
- スマホ幅では、一覧のアプリバーの右の虫めがねを押すと検索画面に切り替わります (「戻る」で閉じます)。
- 以前の検索欄の絞り込み条件 (URL の `from=` など) は、開くと検索欄の書き方 (`from:…`) に直します。
- 探す範囲は、選んでいるアカウント (選んでいなければ全アカウント) の全フォルダです。ごみ箱と迷惑メールは含みません
  (`folder:ごみ箱` のようにフォルダを指定したときは含みます)。
  表示中のフォルダだけに絞ることもできます (ごみ箱の中を探すときは、ごみ箱を開いてこちらを使います)。
- 検索欄では次の書き方も使えます。

| 書き方 | 意味 |
| --- | --- |
| `定例 日程` | 空白で区切った語をすべて含む |
| `"Always Free"` | 空白を含む語句をそのまま探す |
| `-下書き` | その語を含まない |
| `from:佐藤` / `to:tanaka` / `subject:経費` / `body:締め切り` | 探す場所を限定する |
| `has:attachment` / `is:unread` / `is:read` / `is:starred` | 添付あり / 未読 / 既読 / スター付き |
| `after:2026-11-01` / `before:2026-12-01` | その日以降 / その日より前 |
| `folder:受信トレイ` / `in:trash` / `-folder:"仕事 2026"` | そのフォルダにある / 無い。名前は、アプリでの表示名・役割の名前 (受信トレイ・ごみ箱など、英語の inbox・trash でも可)・メールサーバー上の名前やパスのどれかと一致すればよく、アカウントはまたぎます |

API は `GET /v1/messages/search` です。`q` のほかに `accountId`、`scope` (`all` か `folder`) と `mailboxId`、`from`、`to`、`subject`、
`since`、`until` (日付、どちらもその日を含む)、`hasAttachment`、`unread`、`flagged`、`timeZone` (日付の区切りに使う)、`cursor`、`limit` を受け付けます。
結果は新しい順で、`terms` に画面で目立たせる語が入ります。

部分一致は PostgreSQL の `pg_trgm` 拡張の索引で速くしています (マイグレーションが `CREATE EXTENSION` を実行します)。
索引が効くのは 3 文字以上の語で、1〜2 文字の語は全件を順に調べます。全角と半角、ひらがなとカタカナの違いは区別します。

## UI

`apps/web` は shadcn/ui (プリセット `bIkeymG`) を使っています。コンポーネントは `apps/web` で次のように追加します。

```sh
pnpm dlx shadcn@latest add <コンポーネント名>
```

フォントは Gen Interface JP (見出しは Gen Interface JP Display) を `apps/web/src/app/globals.css` で設定しています。
shadcn/ui の CLI がフォント設定を書き換えた場合は、`--font-sans` と `--font-heading` を元に戻してください。

### 画面の URL

表示中のアカウント、フォルダ、メール、検索、下書きの一覧、作成画面は URL に反映します。再読み込みやブックマーク、ブラウザーの「戻る」「進む」で同じ表示に戻れます。
表示はパスで表し、検索の内容だけを `?` 以降に置きます。読み書きは `apps/web/src/lib/route.ts` にまとめています。

| URL | 表示 |
| --- | --- |
| `/` | すべての受信トレイ |
| `/accounts/<ID>` | そのアカウントの受信トレイ |
| `/accounts/<ID>/folders/<ID>` | フォルダ |
| `/unified/<ID>` | 統合フォルダ (自分で作った、複数のフォルダをまとめた一覧) |
| `…/messages/<ID>` | メール (会話) を開いた状態 (`/messages/<ID>`、`/accounts/<ID>/messages/<ID>` なども同じ) |
| `/drafts` | 下書きの一覧 |
| `/starred` | スター付きのメール (全アカウント・全フォルダ)。`/starred/messages/<ID>` でメールを開いた状態 |
| `/outgoing` | 送信待ちのメール |
| `/settings`、`/settings/<カテゴリ>` | 設定。カテゴリごとのページに分かれている (`accounts`、`appearance`、`fonts`、`list`、`reading`、`actions`、`sidebar`、`notifications`、`signatures`、`system`)。広い画面は左にカテゴリの一覧と右にページ、狭い画面は一覧からページへ入る。外観・フォント・メール一覧・メールの表示などは端末ごとに localStorage へ保存する |
| `…/compose/<下書きの ID>` | 作成画面を開いた状態 (何も書いていない新規のメールは `…/compose/new`) |
| `…?q=<語>` | 検索 (絞り込みも `from:` などの書き方で `q` に入れる)。表示中のフォルダだけを探すときは `in=folder`。以前の `from` `to` `subject` `since` `until` `attachment=1` `unread=1` `starred=1` も読める |

Web は静的ファイルとして出力する (Tauri / Capacitor にも同梱する) ので、Next.js のページは `/` の 1 つだけで、パスはブラウザー側で読み取ります。対応するファイルの無いパスを開いたときに同じ画面を返すのは、配信する側の役目です。

- 本番: `deploy/Caddyfile` が、拡張子の無いパスに `index.html` を返す。
- オフライン: サービスワーカー (`apps/web/public/sw.js`) が、保存してある最初の画面を返す。
- `next dev` や、`404.html` しか返さない置き場: 404 の画面 (`apps/web/src/app/not-found.tsx`) も同じアプリなので、そのまま開ける。
- ほかの場所に置くときは、知らないパスに `index.html` を返す設定 (SPA のフォールバック) を入れる。

以前の形の URL (`/?account=<ID>&folder=<ID>&message=<ID>`、`/?view=drafts` など) を開くと、いまの形に書き換えます。

フォルダの切り替えと、メールや作成画面を開く操作は履歴に積みます。メールからメールへの移動と検索欄の入力は、いまの履歴を書き換えます。
ログインしていない状態で開いた URL は、ログイン後にそのまま開きます (`/login?next=`)。
